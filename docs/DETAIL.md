# 会话清理 Session cleanup

把历史会话「停用」：改名、归档，并把这场对话产生的文件集中到工作区的 `手动删除` 文件夹。

## 怎么用

输入框右下角有一个常驻的悬浮按钮 **「⌫ 会话清理」**（开合状态会记住）。

点开后是一个浮层卡片：

- 列出当前工作区所有会话的**标题**与最后活动时间
- **当前正在使用的会话**带「当前」标记，复选框禁用，无法勾选
- 勾选要停用的会话 → **「停用所选」** → 卡片内切换到确认视图
- 确认视图会列出每个会话的改名结果与产物去向，并提示风险
- 点「确认停用」执行，点「取消」回到列表（勾选保留）

## 停用到底做了什么

1. **改名**：标题改成 `已停用 YYYYMMDD`（`session.rename`）
2. **归档**：从工作区导航移除（`workspace.archiveSession`，会先停止运行中的任务）
3. **收产物**：宿主监听 `workspace/session-archived` 事件，读取该会话日志，把它写过的文件移动到
   `<工作区>\手动删除\已停用 YYYYMMDD\`

同一天停用多个时，第二个起会自动加序号：`已停用 20261114-2`（重名保护）。

## 界面上的标记

| 标记 | 含义 |
| --- | --- |
| **当前** | 你正在用的会话；禁用勾选，执行前还有二次拦截 |
| **运行中** | 该会话此刻有任务在跑 |
| **最近** | 3 分钟内有活动，可能选错，确认视图会额外提醒 |
| 已停用 | 标题以 `已停用` 开头，默认隐藏；页脚「显示已停用」可展开 |

## 已知限制

- **不删除任何数据**：归档只是从侧边栏隐藏，会话日志仍在磁盘；产物只是移动，仍在 `手动删除` 里。
- **不能恢复**：本插件不提供「取消归档」，归档后标题会一直是 `已停用 …`。
- **产物按「这场对话引用过的路径」归属**：如果多个会话共同编辑过同一个文件，会被**先停用的那场**带走。
- **只移动文件，不移动目录**：空目录会留在工作区。
- **产物必须仍存在**：日志里记过但后来被删掉的文件自然不会被移动。

## 附带的工具

宿主提供工具 `session_cleanup`，用于排查或手动补做：

| action | 作用 |
| --- | --- |
| `list` | 列出工作区会话（id、时间、日志大小） |
| `scan` | 只读：列出某会话引用过的现存文件 |
| `collect` | 扫描并移动某个会话的全部产物 |
| `move` | 移动指定的文件列表 |

运行日志：`~/.dsh/session-cleanup.log`，记录监听器状态、归档事件、移动数量与失败原因。
